# 同班学生批量反馈

[返回项目说明](../README.md) · [使用手册](user-guide.md)

适用于多个学生使用相同 ACGO 作业和周老师 OJ 比赛的情况。采集仍按每个学生的账号和真实姓名分别执行，提交、未提交题目、部分分与独立比赛条件不会混用。程序通过现有本地 API 建档和分析，不直接改数据库，也不确认报告。

## 准备私有配置

先启动工作台、登录专用 Edge 并保存周老师 OJ 管理员连接。核对团队的具体分组，成员备注名才是学生真名，不能用平台昵称替代。

采集器支持只读 `team_members` 操作：指定 `team_id`、`group_id` 和 `cdp_port`，通过现有 `backend.acgo.run_worker` 获取 `group_name` 和 `members`。名单按页读取并核对人数、重复 ID 和分组；只输出 `user_id` 与备注名，不输出手机号、登录凭据。

将核实后的名单放在 `data/private/batches/` 下的 JSON 配置，示例中的编号需替换：

```json
{
  "base_url": "http://127.0.0.1:8765",
  "team_id": "2000000000000000000",
  "members": [
    {"name": "示例学生甲", "user_id": "1000001"},
    {"name": "示例学生乙", "user_id": "1000002"}
  ],
  "skip_user_ids": ["1000002"],
  "homework": "101,102,103",
  "zhou_contests": ["c1", "c2", "c3"],
  "start_date": "2026-10-01",
  "end_date": "2026-10-05",
  "reference_date": "2026-10-09",
  "tracks": ["J", "S"],
  "target_year": 2026
}
```

`skip_user_ids` 用于跳过已有报告的学生。起止日期限定作品发生时间，`reference_date` 是规划起点。年龄、年级、获奖和讲师观察不从其他学生复制；新学生默认留空，已有档案保留各自资料。主作品采用最新代码，同时保留提交过程；未提交材料也保留。

## 执行与恢复

在 Ubuntu / WSL 根目录执行：

```bash
.venv/bin/python scripts/batch_feedback.py \
  --config data/private/batches/example/config.json \
  --state data/private/batches/example/state.json
```

真实分析调用已配置的 DeepSeek，产生正常 API 费用。脚本一次导入一位学生，每位学生最多同时处理三份采集任务；采集后立即提交报告分析，再导入下一位。分析使用工作台现有的并发与队列规则。

状态文件记录导入、档案及报告 ID；同一配置和状态文件可继续恢复，最多自动恢复失败分析三次，已经完成的阶段不重做。一个状态文件只允许一个控制进程。配置变更后需使用新的状态文件，不能混用原批次。中断控制脚本不会撤销工作台已经接收的采集、分析任务；关闭整个服务则按现有恢复规则处理。

全部任务或题目读取成功才会生成该生报告。同一学生、同一时段已有报告时复用原 ID；相同材料直接使用已有分析，改变材料则覆盖本期报告并重新分析，不产生第二条列表记录。有读取失败、任务过期或分析仍未完成时，检查状态中的 `error`、`failed_tasks` 和 `failed_questions`，在工作台核对，避免把不完整采集误当作完整成果。退出码 0 表示全部报告进入审核，1 表示存在需处理项。

完成后在学生档案或反馈列表打开报告，审核再确认、下载正式 PDF。批量脚本不模拟讲师确认；提前导出的 PDF 应作为待审核预览。名单、状态、日志和学生 PDF 均留在忽略的私有或输出目录，不提交 Git。
