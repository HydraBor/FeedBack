## 先建立学生档案

在“学生档案”新建或选择学生。姓名用于报告显示，年龄、年级用于内部评估和规划，ACGO 数字 ID 用于核对作品归属。获奖经历等放在历史背景中。

姓名不是唯一标识；同名学生拥有不同档案编号。导入时优先选已有档案。未选档案时，提供 ACGO ID 会按该 ID 匹配；只使用周老师 OJ 时按姓名匹配，存在歧义会要求先选档案。ID 与姓名不一致时先核对，系统不会自动合并。

修改档案不会改写已有反馈保存的学生信息快照。已有学生的年龄和年级建议在档案页更新，导入页的这些字段主要用于新建档案。

## 导入多份作业和比赛

“导入做题档案”可以一次填写两个平台的材料：

| 来源 | 要填的信息 | 多份材料格式 |
| --- | --- | --- |
| ACGO 作业 | 学生 ACGO ID、同一团队 ID、作业编号或完整链接 | `26126,26134,26144` |
| ACGO 比赛 | 学生 ACGO ID、同一团队 ID、比赛编号或完整链接 | `22884,22900` |
| 周老师 OJ | 先保存管理员连接，再填比赛编号或链接；按学生姓名匹配 | `c12,c8,c13` |

编号示例只演示格式，不是必须采集的任务。使用英文逗号 `,`，不要使用中文逗号，不要留空编号。重复编号会去重。同一批 ACGO 材料来自同一团队；不同团队分别导入。比赛只有编号无法解析时，粘贴完整比赛链接，保留 `examId`、`matchRoundId` 等参数。

ACGO 首次采集需要在专用 Edge 登录并具备查看团队、学生代码的权限。普通浏览器中的登录不会自动共享。窗口关闭后采集器会尝试重开原配置；登录失效仍需手动登录。周老师 OJ 直接使用本机保存的管理员连接，不需要 Edge。只有指定比赛会被读取，不采集整站目录。同名考生可填写考号并逐场导入核对。

采集并发默认 3 份、可选 1—8，每份作业或比赛由独立进程处理。网络限流时降低并发。题目和提交没有数量上限，大量材料仍会受平台响应、内存和 API 处理时间影响。

### 学习日期从哪里来

- 在“导入做题档案”中，起止日期必须同时填写或同时留空。
- 填写范围后，按北京时间包含起止两天，保留范围内的可核实提交。
- 两个日期留空时，根据指定任务内实际提交的最早、最晚日期生成档案时段；没有可靠提交日期时会要求补填。
- 从档案“带入反馈”时沿用档案时段。在“新建反馈”直接读取作品，必须先选择学生、填写学习起止日期及平台编号。
- 学习结束日期不会自动变成今天。资料基准日期用于规划起点，不是学习结束日期；分析、导出和文案更新都沿用已保存的本期时段。

平台来源时段必须与反馈时段一致。带入后若需要另一个日期范围，重新按该范围导入，避免把其他日期的代码当成本期成果。

### 采集完成后先核对

查看作业、比赛数量，读取失败任务和失败题目，以及日期警告。部分任务失败时成功材料仍会保存，不能把“采集完成”理解为所有任务都成功。

题目卡片默认折叠，点击后查看题面、最新代码、原有成绩和提交过程。可全选、全不选、反选，再把需要的题目带入反馈。最新代码作为主作品，早期失败和后续修改仍保留；最新失败不会被历史 AC 偷换为通过。

没有提交的题目也保存题面，供判断本期覆盖范围。可补充“尚未理解”“课堂时间不足”“不要求完成”等原因；原因未知不会自动认定不会做、扣零分或归因于态度。

## 填写本期反馈材料

选择目标 CSP 年份及 J、S 或两组。已公布日程用于规划到目标 CSP，并列出最近 2—4 周重点；目标考试已结束时应选择后续年份。资格未知就留空，不要把系统定位当作取得第二轮资格的证明。

补充讲师观察、知识点、获奖背景与已知完成条件。每道题可标记是否独立、是否看过题解、实际耗时；未知留空。默认课堂作业为先尝试后讲解，不记得讲解时点就只分析早期尝试和后续变化，不猜测哪版发生在讲解前。

比赛导入默认带有“限时独立完成、未接受讲解”的讲师确认；特殊情况应取消确认或在题目中修改。OI/CSP 只有最终作品时，一份记录不表示只尝试一次。相邻提交间隔只是参考，不能填写成实际连续做题时间。

专注投入采用讲师提供的 1—100 分；未观察到就留空。其余五项能力先由 API 依据材料评分，讲师观察供参考。年龄、年级和专注分都不会作为独立文字字段放进家长 PDF。

同一学生、同一学习时段只保留一份当前报告，不同学习时段分别保存。从做题档案再次生成同一期反馈时更新原报告；材料没有变化则直接打开已有报告。演示报告与真实报告分开保存。

在审核页点击“修改本期材料”，可以补充观察、调整完成条件或作品；保存变更后清除旧分析并重新分析，报告 ID 保持不变。学生及学习时段不能在这个入口更换，新时段请另建反馈。原始旧稿与已确认版本保留，正在分析或更新文案时不能替换材料。

## 分析、恢复和更新文案

系统依次进行逐题分析、知识与能力评分、历年 CSP 对照、训练安排和家长写作。逐题和历年卷受控并发，默认 4、最多 8，可在本地设置调整，对新分析或恢复分析生效。

每题及阶段完成后保存。显示“38 / 38”只代表逐题诊断完成，后面仍有评分、历年预测、训练和写作阶段。遇到空内容、结构错误、限流或网络中断时，先处理连接问题，再点击“恢复分析”；通过校验的阶段会复用，无需删除重建。程序重启后，未完成分析标记为可恢复，已完成内容保留。

分析已经完成后，“更新建议与文案”复用逐题诊断、评分和等级定位，只刷新建议与文字并覆盖当前报告，不新增列表记录。仅需改几句话时直接手动编辑。更新会调用 DeepSeek，成功后回到待审核；失败时原草稿及确认版保留。原有定位不会因只更新文案而重新计算。

演示模式用于检查流程和排版，不代表真实学生评价，报告会明确标注，也不参与历史依据。

## 审核与导出

在讲师审核页核对：本期成果、知识评分与证据、六项能力、CSP 定位、下一阶段建议和推荐题单。正文应只说家长听得懂的具体表现，做题称“题目”，不罗列题名、算法实现或提交统计。自动检查提示需处理后才能确认。

标题默认仅学生姓名，可自由编辑。知识分可以调整，需保留已经分析的本期标签；系统记录讲师改分。知识图从有效分数中选最高六项，图上按固定标签顺序排列，一两项改条形图。完整评分在审核页保留，不因主图选高分而丢弃其他项。

图下统一三行两列评分注解：

| 分值 | 家长解释 |
| --- | --- |
| 1—20 | 能理解老师讲的 |
| 21—40 | 在提示下能完成练习 |
| 41—60 | 能独立做基础题 |
| 61—80 | 能独立做综合题 |
| 81—100 | 能灵活运用讲清做法 |

能力主要通过文字表达；题单单独列在“配套练习题单”，四列、普通文字和跳转提示，不限两份，不细化到具体题目。推荐链接由已核实题单记录生成，不能手填任意未经核实的题单链接。

先预览，保存修改，再“确认版本”并下载 PDF。默认 A4 一页，长内容自动分页，每页底部保留说明与页码。PDF 不显示资料基准或“待审核预览”字样。确认时保存独立 HTML 快照，首次下载生成 PDF；模板或文案以后修改不会覆盖旧确认版。想应用新排版，应另行确认一个新版本。

多个窗口同时编辑导致“内容已更新”时，刷新后核对最新版本再保存；不要反复提交旧页面。定期从“本地设置”下载备份，恢复操作见[维护手册](operations.md#备份与恢复)。删除学生会连同其做题档案、反馈和确认文件一起删除，日常使用应谨慎核对姓名。
